# AI session record

The full Claude Code sessions behind this project, exported by the owner with `/export` before each `/clear`. Files are numbered in the order the work happened.

| File | What it covered |
|---|---|
| `01-plan.txt` | Interview with the owner, live checks of five data sources, the plan, a review of the proposed weights against measured warning lengths, and milestone 0 (repository scaffold and working rules). |
| `02-data.txt` | The order of work re-checked against the assignment, then milestone 1: the hub list, parsers for the three sources written test-first on recorded responses, the fetch step and the offline database build, the data report and what it showed, and two independent reviews whose findings led to a wider warning request, three more checks in the build and fifteen more tests. Also a fix to the handoff skill so the next session's prompt is saved and shown to that session when it starts. |
| `03-scoring-and-agent.txt` | Milestones 2 and 3. The score: warning time merged per hazard and split by local year, test-first on hand-built warning lists, then the first real ranking and the review point (band cut-offs, coastal and area flood warnings, FEMA's hurricane defaults, a check of published evidence on whether some hazards disrupt more than their warning time shows). Confidence rules, the six tools, the fourteen evaluation cases and their graders. Then the agent on Claude Opus 5.5: a spike, the loop with validation, repair and grounding, the first paid evaluation runs, and two fresh-context reviews whose findings were checked against the code and fixed, with the owner deciding every rule that changes what counts as a valid answer. |
| `04-api.txt` | Milestone 4. The behaviour choices the plan left open, settled with the owner: HTTP status, conversations the server no longer holds, Markdown in the page, a time limit per message. A finding that the SDK waits however long the API asks before a retry, which moved the retry into the agent loop. Error codes in the agent's reply, the FastAPI app and the one-page chat, test-first on the scripted fake model, and `wra serve`. A fresh-context review whose three bugs and smaller findings were checked against the code and fixed. A paid check of a question and its follow-up through the API, and the owner's check of the four assignment questions in the page. |
| `05-results.txt` | Milestone 5, on Claude Opus 5.5. Terms explained where they appear (queue q13), from a survey of every unexplained term and the Weather Service's own definitions. The end-to-end script, the evaluation target check, and the architecture and summary documents, the summary written for the analysts' manager. Paid runs: three repetitions on Opus, Sonnet and Haiku; three of our own checks found failing right answers and fixed with the owner; a diagnosis of Sonnet's repeated tool calls (effort, a prompt line and a loop guard tested, none curing it). The owner chose Haiku. A fresh-context Fable review of the whole repository, its eight findings checked and fixed, and the final end-to-end run passing at 42 of 42. |
| `06-closeout-and-deploy.txt` | Milestone 5 closed and the public URL, on Claude Opus 5.5. The final end-to-end check re-run on the shipped code (42 of 42), a queue-guard rule, two global instruction lines and the page check by hand. Then the public URL (queue q10): a design read by a fresh Fable reviewer as its builder, a plan, and the build: public mode with sign-in and a daily cap on questions, a cap on conversations held, a Dockerfile; a Fable whole-branch review and its fixes; the repository made public on GitHub; the host changed from Koyeb's free instance to Render's paid one after the start-up measured about 42 seconds at the free size. Last, the documents tightened for reviewers. Two words are reworded in this file: the name of another of the owner's projects and the name of a work system. |
| `07-score-change-alert.txt` | The score-change alert, the assignment's second bonus, on Claude Opus 5.5, with Fable writing the design and reviewing the whole build. First the session 06 transcript, committed after a counts-only scan. The owner chose the alert over voice, for the brief's narrow scope, and an issue in the public GitHub repository as where it lands. Fable's design measured that a fresh fetch moves no score, since the scored years are finished; its facts were checked against GitHub's and Render's documentation and measured again, and a fresh reviewer read it as its builder. A plan, then the build test-first, in parallel where files did not overlap: the comparison and its message, the `wra alert` command with a reviewed copy of the ranking, and a weekly GitHub job allowed only to read the code and write issues. A Fable whole-branch review found that a failed duplicate check could open a second public issue (fixed) and moved the schedule to Thursdays. Merged and pushed. |
